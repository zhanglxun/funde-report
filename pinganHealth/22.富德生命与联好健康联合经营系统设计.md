# 富德生命与联好健康联合经营系统设计

## 一、为什么单独形成22号文档

把本轮内容全部塞入21号文档有三个问题：

1. **对象不同。**21号面对产品、渠道与服务设计；本文面对集团管理层、财务、组织、人力、技术、合规和联合项目负责人。
2. **问题层级不同。**21号解决产品定义和履约；本文解决跨法人协同、利益分配、经营核算和组织权责。
3. **失败原因不同。**产品不成立通常是客户价值不足；联合经营失败更多是客户归属、预算、KPI、数据边界和收益分配没有解决。

因此采用“**独立成篇、双向链接、21号保留关键摘要**”的方式。这样既不破坏21号的产品结构，也不会遗漏决定业务能否落地的机制。

## 二、从全部研究中得到的十二个底层结论

### 1. 平安真正的壁垒不是服务项目多，而是控制了四个节点

| 控制点 | 具体内容 | 缺失后的结果 |
|---|---|---|
| 支付入口 | 保费、团险、企业健康预算、健康保障委托资金、客户自费 | 服务有需求但没有稳定支付方 |
| 客户关系入口 | 代理人、保单客户、企业员工、家庭账户 | 有服务能力却无法低成本触达客户 |
| 服务调度入口 | 家庭医生、健康顾问、养老管家、企业医务室 | 服务供应商各自为战，客户不知道找谁 |
| 供给履约网络 | 医院、医生、药店、体检、康复、护理和养老 | 权益写得很好，但关键时刻无法兑现 |

富德不能只建设其中一个节点。一个健康APP、一批医院资源或一套会员权益，都不等于联合经营能力。真正的护城河是把四个节点组织成一条可重复的经营链。

### 2. 深度融合不是两个法人合成一家，而是业务流程高度嵌合

```text
保险客户产生服务资格
        ↓
联好完成激活、建档和日常运营
        ↓
客户在咨询、就医、慢病、康复和养老场景使用服务
        ↓
联好回传激活、工单、完成和满意度等经营状态
        ↓
富德生命用于客户关怀、续期、服务升级和转介绍经营
```

与此同时，保险责任、医疗责任、资金账户、法人账、原始健康数据仍应保持边界。保险和健康的“你中有我、我中有你”，是**流程相互嵌入、产品相互增值、经营结果相互影响**，不是无边界的数据和资金混合。

### 3. 健康是不是基础设施，不取决于APP放在哪里

健康服务放在保险APP内，并不必然是错误；单独做健康APP，也不必然成为入口。真正的判断标准是健康服务是否拥有：

- **流程权**：投保、保全、体检、理赔、续期能否触发服务；
- **客户经营权**：健康团队能否在授权范围内持续触达和服务客户；
- **预算权**：服务是否有稳定年度预算，而不是临时活动经费；
- **结果责任**：健康团队是否对激活、使用、履约、满意度和成本负责。

因此，富德当前最需要讨论的不是“哪个APP做首页”，而是健康服务在保险主流程中有没有上述四种权。

### 4. 健康基础设施成立，需要五项条件同时满足

1. **产品嵌入**：服务与保单、客户等级或企业方案形成正式关系；
2. **生命周期同步**：保单或企业合同有效期间，基础服务持续有效；
3. **首次关系建立**：现场或线上完成激活、建档和第一次体验；
4. **主动运营**：复查、复诊、续方、慢病、体检异常和年度回顾能够主动触发；
5. **经营结果回流**：保险侧获得必要的激活、完成、满意度和客户关怀状态，而非原始病历。

只满足“采购服务”和“上线入口”，健康仍然只是供应商；五项条件同时成立，才可能成为保险经营基础设施。

### 5. 健康不必成为微信式日活入口

健康业务包含两种频次：

- **持续轻触达**：运动、睡眠、用药提醒、健康计划、日常咨询和慢病随访；
- **低频高价值**：体检异常、专家二诊、住院、重疾、康复和父母养老。

因此不应把“每天打开APP”作为模式成立的前提。更准确的公式是：

> **持续轻触达维持关系，关键时刻高价值履约建立信任。**

对保险而言，关键时刻形成的服务记忆，可能比普通日活更能影响续期、加保和转介绍。

### 6. 真正缺失的可能不是产品，而是客户关系移交机制

保单生效后的现场激活，不是一个小运营动作，而是三种关系的建立：

- 客户与富德生命的保障关系；
- 客户与代理人的持续服务关系；
- 客户与联好健康团队的专业健康服务关系。

如果客户没有完成激活、建档、首问或第一次报告解读，联好只是拿到一个理论客户名单，并没有获得可经营的服务关系。

### 7. 最难的问题不是数据，而是利益分配

寿险可能认为健康服务是成本；联好认为寿险不给客户和预算；代理人认为服务占用时间却不计业绩。三方激励不一致时，产品不会自然落地。

联合经营必须回答：

- 谁因续期、升单、转介绍和企业续约获益；
- 谁承担基础会员、高成本履约和市场活动费用；
- 服务带来的增量价值如何归因；
- 代理人为什么愿意推动激活和使用；
- 联好如何从“被采购的成本中心”变成对经营结果负责的服务运营主体。

### 8. F端、B端和C端不能建设三套独立供应链

三端应共用家庭医生、服务工单、医院医生网络、供应商采购、质控、结算和授权中心。差异只在支付方、获客入口、权益规则和服务等级。

| 模式 | 主要支付方 | 获客入口 | 主要权益规则 |
|---|---|---|---|
| F端 | 保险公司、保单客户 | 代理人、保单、客户活动 | 保单类型、客户等级、次数和限额 |
| B端 | 企业、团险、健康委托资金 | HR、工会、企业医务室 | 企业套餐、员工层级、年度预算 |
| C端 | 家庭个人 | 医院、线上入口、企业员工家属 | 会员费、周期包、按次购买 |

### 9. B端最终可以形成B2B2C增长飞轮

```text
企业为员工购买基础服务
        ↓
员工激活、建档并完成第一次体验
        ↓
员工本人或家属产生高阶需求
        ↓
企业增购／委托资金支付／个人自费升级
        ↓
形成家庭客户关系和更多服务使用
        ↓
企业获得更强福利感知，支持次年续费
```

该飞轮必须遵守授权和营销边界，不能因为员工使用健康服务就进行疾病定向保险营销。

### 10. 企业健康小屋不是最终交付中心，而是激活与转化中心

健康小屋、医务室和线下活动最重要的作用，是完成身份绑定、首次检测、风险识别、线上医生连接和后续服务转介。如果只看检测人次，最终容易成为闲置设备。

### 11. 健康平台的核心资产是“服务控制塔”，不是服务清单

服务控制塔至少包括：统一身份与授权、权益规则引擎、服务工单、分诊和升级、供应商调度、SLA监控、费用结算、投诉质控、客户回访和经营分析。没有控制塔，平台只是服务聚合页。

### 12. 富德应先选择楔子场景，而不是同时覆盖所有客户

初期场景必须同时满足：客户密度足够、痛点强、价值容易感知、交付可标准化、成本可控、与保险或企业经营结果相关，并能在6—12个月验证。

## 三、联合经营的总体架构

```text
                       联合经营委员会
           战略、年度预算、产品规则、利益分配、重大风险
                              │
     ┌────────────────────────┼────────────────────────┐
     │                        │                        │
富德生命业务域             联好健康运营域             共享服务控制塔
产品/渠道/保单/续期         激活/健康管理/履约          账户/权益/工单/SLA
客户分层/企业关系           供应网络/服务质控            结算/授权/经营分析
     │                        │                        │
     └──────────客户旅程与服务工单连接，责任和数据分域──────────┘
                              │
        医院｜医生｜药房｜体检｜康复｜护理｜养老服务网络
```

### 1. 富德生命负责什么

- 确定保险产品、客户等级和服务资格；
- 提供合规的客户触达入口；
- 将服务嵌入投保、保全、理赔、续期和客户活动流程；
- 按合同采购基础服务或高端客户权益；
- 管理代理人和分公司的激活、转介和客户关怀行为；
- 不介入医学判断，不默认访问原始医疗健康信息。

### 2. 联好健康负责什么

- 完成服务激活、家庭建档和首次服务；
- 承担健康咨询、评估、随访、管家和服务调度；
- 管理医院、医生、康复、护理和养老供应商；
- 对服务SLA、成本、满意度、投诉和闭环负责；
- 向保险侧回传白名单内的经营状态；
- 在明确授权和边界内承接客户自费升级。

### 3. 代理人与健康团队的边界

| 事项 | 代理人 | 健康团队 |
|---|---|---|
| 解释保险责任 | 负责 | 不替代代理人解释保险销售事项 |
| 介绍和激活健康权益 | 引导并协助 | 负责专业说明和首次服务 |
| 医疗建议 | 不提供 | 由合格医生或专业人员提供 |
| 服务进度 | 可看客户授权后的必要状态 | 负责完整工单管理 |
| 原始病历和健康指标 | 不查看 | 在履约必要范围内处理 |
| 续期、加保 | 代理人依法依规负责 | 仅提供非诊疗的服务完成状态，不以疾病推动营销 |

## 四、客户关系移交与激活机制

### 1. 建议设计“保单生效后30天激活旅程”

| 时间       | 动作                    | 第一责任人    | 结果       |
| -------- | --------------------- | -------- | -------- |
| T日：保单生效  | 展示服务资格，完成一键授权和账号绑定    | 代理人/保险系统 | 服务资格可见   |
| T+1至7日   | 家庭成员绑定、需求问卷、选择健康联系人   | 联好健康管家   | 建立服务关系   |
| T+7至15日  | 完成一次咨询、报告解读或健康评估      | 联好专业团队   | 形成首次价值感知 |
| T+15至30日 | 根据需求给出下一步计划，未使用客户二次触达 | 联好运营团队   | 首月激活闭环   |
| 以后按季度/事件 | 主动提醒、服务触发和年度回顾        | 联好+代理人   | 形成持续关系   |

### 2. 不是发账号，而是完成“第一次有效服务”

真正的激活指标不应是短信已发送、APP已下载，而应至少区分：

- 资格触达率；
- 账号激活率；
- 家庭建档率；
- 首次有效服务率；
- 30天二次使用率；
- 90天留存或服务关系保持率。

### 3. 归因与激励

- 代理人完成合规激活和首次服务引导，可计入客户经营积分；
- 医疗咨询次数本身不应直接转化为销售业绩；
- 因服务产生的续期、升级和转介绍，应设置可审计的归因窗口和规则；
- 健康团队以激活质量、服务完成、满意度和单位成本考核，不能只考核触达量。

## 五、利益分配、预算与项目P&L

### 1. 基本原则：谁获得价值，谁承担相应成本

| 价值获得方  | 获得的价值                   | 合理承担方式             |
| ------ | ----------------------- | ------------------ |
| 富德生命   | 保单价值感知、续期、升单、转介绍、客户分层经营 | 采购基础会员和特定保单权益      |
| 企业客户   | 员工福利感知、运营外包、健康风险支持      | 按人年费、项目费、驻场费、委托资金池 |
| 个人家庭   | 超出基础权益的高阶、家属或专项服务       | 会员费、周期包、按次自费       |
| 联好健康   | 服务运营收入、供应链规模和客户关系       | 对交付、成本、满意度及转化承担责任  |
| 代理人/渠道 | 更强的客户经营和销售工具            | 获得服务激活和经营协同激励      |

### 2. 建议拆成五类预算，不要混成一笔“健康费用”

1. **基础会员预算**：覆盖全量或指定保险客户的标准化低成本服务；
2. **高价值客户权益预算**：对应高保额、高端医疗、长期缴费或特定等级；
3. **专项服务预算**：慢病、康复、养老等周期项目；
4. **渠道激活与运营预算**：活动、首用、客户教育和二次触达；
5. **企业委托及实付预算**：企业预付资金池和按次履约费用。

### 3. 联合项目P&L

每个产品或试点至少单独核算：

```text
联合项目收入/价值
= 寿险采购收入
+ 企业年度服务收入
+ 客户自费收入
+ 合规供应链服务收入
+ 可验证的续期、升级等增量贡献

联合项目成本
= 医生与健康管理人力
+ 第三方履约采购
+ 渠道激活与运营
+ 技术与客服分摊
+ 投诉、退款和质量损失
```

不能把寿险向联好的关联采购收入直接视为集团新增价值。集团视角需要区分：

- **内部结算收入**：解决法人间资源投入与绩效评价；
- **外部真实收入**：企业、个人和外部客户支付；
- **保险协同价值**：续期、升单、获客效率等经对照验证的增量；
- **长期能力价值**：客户关系、供应网络和数据运营能力。

### 4. 内部定价原则

- 标准化服务采用市场可比价格或成本加合理利润；
- 高成本服务按次数、限额或实际履约结算；
- 对未激活、未履约和未达到SLA的服务设置扣减规则；
- 关联交易合同明确服务目录、人数口径、有效期、质量和审计权；
- 集团层面评价不能只看联好收入，也不能只看寿险费用下降，而要看联合项目整体价值。

### 5. 平安经验对照：哪些已验证，哪些是建议设计

> [!warning] 证据等级说明
> 平安人寿与平安健康之间的服务费金额、权益成本在寿险产品中的分摊方式、代理人医养专项佣金，**均无公开披露**。下表按证据等级区分，写入方案时不得把“建议设计”表述为“平安已验证”。

| 机制            | 平安做法                                                                                                                                               | 证据等级             | 富德对应设计                                                   |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- | -------------------------------------------------------- |
| 权益发行与履约分离     | 权益由平安人寿向符合条件的会员提供，**委托**平安健康或其他合作服务商执行（[平安居家](https://www.pingan.com/official/strategyDetail/28164504)）                                            | 公开披露             | 富德生命为权益**发行方**，持有客户关系并承担付费；联好为**受托履约方**，对SLA、成本、满意度负责    |
| 权益与保单档位硬绑定    | 权益资格挂在保单类型和累计保费门槛上；健康险服务成本受10%/2%监管上限（见[[10.平安代理人渠道与健康管理协同机制]]）                                                                                    | 公开披露             | 建立“保单档位→权益包→预算比例”对照表，预算在产品设计阶段确定，而非年度谈判                  |
| 内部销售定价        | 平安健康向平安集团提供的服务：在线医疗按成本加成，且**不低于向独立第三方收取的价格**；预付卡按面值；商城商品按采购成本加预期回报（2020年框架协议，见下文）                                                                  | 公开披露（2020年版）     | 联好对寿险定价设“成本加成 + 不低于外部可比价”双约束，防止内部低价补贴                    |

| 代理人激励         | 公开材料仅见继续率奖、长期服务奖、养老公积金和功勋荣誉体系（[21世纪经济报道](https://m.21jingji.com/article/20250527/herald/cec3ec7b93db146d078f1244ec63e44b_zaker.html)），**未见医养专项提成** | 公开披露 + 推断        | 优先把激活与首次服务纳入既有“客户经营/继续率”考核，不另设销售提成，避免触碰“健康服务作为保险对价”的监管边界 |

**平安健康2020年与集团的持续关连交易框架协议（2021–2023年度上限）**

数据来源：平安健康2020年8月公告的[续期公告](https://www.marketscreener.com/quote/stock/PING-AN-HEALTHCARE-AND-TE-44548681/news/Ping-An-Healthcare-and-Technology-RENEWAL-OF-CONTINUING-CONNECTED-TRANSACTIONS-31149291/)。该版本已过期，**仅用于理解结构，不代表当前金额**；年度上限是上限，不是实际发生额。

| 方向 | 内容 | 2021 / 2022 / 2023年度上限（亿元） |
|---|---|---|
| 平安付费给平安健康 | 在线医疗、预付卡与体检套餐、健康商城、广告 | 50.0 / 64.0 / 87.0 |
| 平安健康付费给平安 | 咨询、业务推广、外包行政、保险服务、流量导入、客户转介 | 8.9 / 12.6 / 16.4 |

由此可看出两点：

1. **销售端上限约为采购端的5至6倍**，说明平安健康主要是集团内部的服务供应方，采购端（含渠道转介）是规模较小的反向流。
2. 平安健康向集团支付了**客户转介和流量导入费**。这说明平安内部并非“寿险免费导流、健康公司白拿客户”，渠道端也有付费机制。具体费率未披露，建议富德在设计联好对寿险的转介结算时，将此作为可行的结构参照，费率需自行测算并经合规审查。

**待核实**：2024年3月19日平安健康另有“2024年服务购买协议”公告，当前版本的上限与定价原则应以其及2025年报“持续关连交易”章节为准。

## 六、F端、B端、C端共用的服务控制塔

### 1. 应共用的能力

- 统一身份和家庭关系；
- 客户授权与用途管理；
- 保单、企业和个人会员权益规则引擎；
- 服务受理、分诊、升级和工单系统；
- 医生、医院、药房、康复、护理和养老资源调度；
- SLA、费用、结算、投诉和质控；
- 客户回访、满意度和经营分析。

### 2. 不应共用或默认打通的内容

- 原始病历、问诊记录和体检报告不能向保险销售端开放；
- 企业不能查看员工个体医疗健康信息；
- 代理人不能因客户疾病标签获得营销名单；
- 核保、理赔需要的医学资料应通过对应流程单独取得；
- 不同法人的资金、收入成本和税务处理必须独立。

### 3. 可以合规回流的经营白名单

- 服务资格是否生效；
- 是否完成激活和首次服务；
- 服务工单状态和是否闭环；
- 服务类别、次数、时效和满意度；
- 是否需要非医疗性质的客户关怀；
- 企业层面的去标识化、聚合使用数据。

## 七、健康小屋和线下活动的正确经营定位

### 1. 线下节点的七个任务

1. 身份绑定；
2. 权益激活；
3. 首次检测或体验；
4. 风险初筛；
5. 建立线上家庭医生/健康顾问关系；
6. 将异常和需求转为后续服务工单；
7. 为企业或分公司形成可复盘的运营证据。

### 2. 应考核的指标

| 不足够的活动指标 | 更重要的经营指标 |
|---|---|
| 到场人数 | 到场客户激活率 |
| 检测人次 | 检测后咨询和服务承接率 |
| 异常发现率 | 异常客户获得解释和下一步方案的比例 |
| 讲座场次 | 30/90天持续服务率 |
| APP下载量 | 首次有效服务完成率 |
| 设备使用次数 | 高风险人群随访率、企业续费证据 |

### 3. 线下节点不必全部重资产自建

根据客户密度选择移动活动、定期驻场、健康站、企业医务室等不同形态。只有当当地客户规模、使用强度和履约需求能够覆盖固定成本时，才升级为长期驻点。

## 八、从线性闭环升级为增长飞轮

```text
保险/企业提供支付和客户入口
        ↓
激活与第一次有效服务
        ↓
轻触达维持关系 + 关键时刻深度履约
        ↓
形成信任、服务记忆和家庭延伸需求
        ↓
续期、升级、企业续约、家属付费和转介绍
        ↓
更多预算和订单进入联好服务网络
        ↓
供应规模扩大、采购成本下降、履约密度提高
        ↓
服务体验进一步提升
```

这一飞轮成立的关键，不是简单追求咨询量，而是每一环都有明确责任人、成本和转化指标。

## 九、价值证明与指标体系

### 1. 四层指标

| 层级 | 核心指标 | 用途 |
|---|---|---|
| 激活层 | 资格触达、账号激活、家庭建档、首次有效服务 | 判断客户关系是否真正建立 |
| 服务层 | 响应、完成、闭环、满意度、投诉、单位成本 | 判断履约质量与效率 |
| 经营层 | 续期、升级、转介绍、企业续约、家属付费 | 判断是否产生经营价值 |
| 健康与风险层 | 随访、复诊、依从性、风险变化、赔付影响 | 需较长周期和对照验证 |

### 2. 不应过早承诺的指标

- 不应以短期活动直接承诺降低赔付；
- 不应把使用服务客户的高续期率直接认定为服务导致；
- 不应将异常发现数量等同于健康改善；
- 不应把APP日活作为所有客群的核心成功标准。

### 3. 建议的验证方法

- 同客群、同产品、同渠道设置试点组和对照组；
- 同时观察使用客户与被邀请但未使用客户，降低选择偏差；
- 分开计算内部采购收入、外部收入和保险协同价值；
- 对续期、赔付等结果设足够观察周期；
- 预先定义成功阈值和停止条件，避免事后挑选有利指标。

## 十、楔子场景选择与首期建议

### 1. 选择标准

| 维度 | 判断问题 |
|---|---|
| 客户密度 | 富德是否已有可集中触达的客户群？ |
| 痛点强度 | 客户是否愿意立即使用，而不是只口头认可？ |
| 价值可见 | 一次服务后是否能明确感受到帮助？ |
| 标准化 | SOP和供应网络能否复制？ |
| 单位经济 | 成本是否可计算、可分层、可控制？ |
| 经营关联 | 能否关联续期、升单、企业续约或外部收入？ |
| 验证周期 | 是否能在6—12个月获得可信结果？ |

### 2. 可选楔子

- 中高端保险客户体检异常后的解释—就医承接；
- 重疾客户确诊后的二诊—就医—康复协同；
- 银保或高净值家庭的父母健康与养老支持；
- 企业员工体检后的异常管理；
- 高血压、糖尿病等标准化慢病周期管理；
- 孕产家庭的院内院外周期服务。

### 3. 推荐首期组合

不建议同时启动全部场景。更合理的是“一主一辅”：

- **主场景：体检异常后的解释—复查—就医承接。**覆盖个人客户和企业员工，痛点清晰、首次价值感知强，也容易与线下活动连接；
- **辅场景：选择一个标准化慢病周期包。**用于验证持续运营、依从性、单位成本和年度续费逻辑。

高端就医、重疾和养老作为重点客户定向能力建设，不在首期做全客群承诺。

## 十一、组织治理和会议机制

### 1. 联合经营委员会

由富德生命业务、联好健康、产品、渠道、财务、技术、数据、合规和客服共同组成，负责：

- 年度产品与客群选择；
- 预算和内部采购；
- KPI与收益归因；
- 数据白名单和重大合规事项；
- 供应网络和重大服务事故；
- 试点扩张、调整和停止决策。

### 2. 联合项目办公室

日常负责版本、排期、渠道培训、客户激活、服务交付、数据报表、问题升级和季度复盘。每个重点产品必须只有一个端到端业务负责人，不能由保险、联好和技术分别负责局部而无人对整体结果负责。

### 3. 三张共同报表

1. **客户经营表**：资格、激活、首用、留存、续期和升级；
2. **服务运营表**：工单、SLA、成本、满意度、投诉和供应商；
3. **联合财务表**：内部采购、外部收入、履约成本、渠道成本和增量贡献。

## 十二、分阶段落地与决策门槛

| 阶段          | 重点                       | 必须证明                 | 不通过时的处理          |
| ----------- | ------------------------ | -------------------- | ---------------- |
| 0—3个月：机制准备  | 权责、合同、数据白名单、P&L、SOP和试点客群 | 三方责任清楚，服务可交付，数据合规    | 不急于大规模获客，先补机制    |
| 3—6个月：关系建立  | 激活、首用、服务闭环               | 客户愿意使用，首次价值明确，成本可计算  | 调整入口、话术、权益或客群    |
| 6—12个月：商业验证 | 续期/续约、升级、自费和单位经济         | 至少一种经营价值可重复出现        | 停止无转化的权益，保留高价值场景 |
| 12—24个月：复制  | 城市、渠道、企业和产品扩张            | SLA、毛利/成本和客户体验在扩张后稳定 | 控制城市和供应商扩张速度     |

### 规模化前至少满足

- 激活不是依赖一次性行政推动；
- 首次有效服务率达到预设目标；
- 重点服务SLA和投诉率稳定；
- 单位成本随规模扩大不失控；
- 渠道愿意持续使用而非只配合试点；
- 至少一种外部收入或保险经营增量得到初步验证；
- 数据、合同和关联交易通过合规审查。

## 十四、最终结论

富德与联好要复制的不是平安的服务目录，而是平安背后的联合经营机制：

> **富德生命提供支付容器、客户入口和保险场景；联好健康提供专业服务关系、运营控制塔和医养履约网络；双方通过清晰的预算、合同、数据白名单、客户移交和价值分配，把两个法人连接成一条合规经营链。**

最需要优先补齐的不是更多产品，而是三件事：

1. **客户关系如何从保单资格转化为真实健康服务关系；**
2. **服务创造的增量价值如何核算、归因和分配；**
3. **服务使用如何持续转化为保险经营、企业续费和健康业务收入。**

这三件事解决后，[[21.富德保险与健康服务产品规划]]才会从一套产品方案升级为富德生命与联好健康的联合经营系统。
