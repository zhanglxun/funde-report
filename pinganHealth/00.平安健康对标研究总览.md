# 平安健康对标研究总览

## 核心判断

- 平安健康的本质，是连接保险、金融及企业支付方与医疗养老供应网络的服务管理平台。
- F端通过医疗、健康和养老权益提高保险产品的获客能力、客户黏性、客单与二次转化。
- B端通过“商业保险 + 健康保障委托 + 医疗健康服务”进入企业员工福利、补充医疗和健康管理场景。
- 两端共同依托家庭医生、养老管家，以及到线、到院／到店、到家、到企的服务网络完成交付。

## F端与B端的关键差异

| 维度 | F端 | B端 |
|---|---|---|
| 决策者 | 个人／家庭 | HR、行政、财务、采购、工会、老板 |
| 核心场景 | 客户活动、家庭需求、保单服务权益 | 团险续保、招投标、大客户方案、企业福利运营 |
| 成交关键 | 医疗／养老服务的确定性 | 成本、员工体验、运营能力、服务网络 |
| 活动角色 | 获客、体验、转化 | 签约后的交付、员工激活、续约证明 |
| 后续经营 | 家庭权益使用、加保、转介绍 | 服务数据、满意度、年度复盘、续约扩容 |

## 富德健康管理板块：立项框架10步叙事

图片的10步本质是一条完整的立项论证链：**外部趋势 → 客户问题 → 需求验证 → 竞争定位 → 战略机会 → 产品解法 → 商业闭环 → 价值证明 → 落地路径 → 风险控制**。

## 总叙事主线

**富德健康管理不应只是增加若干健康服务，而应基于保险客户与生态资源，从“事后理赔”走向“事前预防、事中管理、事后康复”的健康经营体系。**  
通过分层服务和可商业化的产品组合，既提升客户健康与体验，也降低保险经营成本、增强客户黏性，并形成健康管理板块自身的收入与生态能力。

## 富德健康管理板块：立项框架10步叙事

| 步骤              | 要回答的核心问题                 | 在汇报中的叙事内容与产出                                                                                                                                      |
| --------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. 产业链调研**    | 为什么是现在？为什么富德要做？          | 从人口老龄化、慢病增长、医疗费用上升、医保支付改革、数字医疗与AI等趋势切入。说明健康管理正从“可选服务”变成保险、医疗、养老共同需要的基础能力；梳理“保险支付方—健康管理平台—医疗服务机构—药械/体检/养老—客户”的产业链，并明确富德的资源位置。                      |
| **2. 客户客观现状调研** | 富德现有客户和业务，到底遇到了什么问题？     | 不泛泛谈行业，而是回到富德自身：客户目前如何获得健康服务？投保、就医、理赔、康复之间是否割裂？服务使用率、续期、投诉、理赔成本、慢病客户管理等存在哪些问题？再按照个人客户、团险企业客户、银保客户、高净值客户、养老客户等做初步分层。                               |
| **3. 客户需求调研**   | 客户真正愿意为什么付费、留存或转介绍？      | 把需求从“我要健康”拆成具体场景：健康咨询、体检解读、就医协助、专家二诊、慢病随访、用药管理、康复护理、养老健康等。进一步区分：**高频基础需求、关键时刻的高价值需求、长期慢病管理需求**；形成优先客群与优先场景。                                       |
| **4. 竞品调研**     | 市场已有解法是什么？富德不能只是复制什么？    | 对标保险公司健康管理、互联网医疗平台、体检机构、商业健康险TPA、养老/康养机构等。重点不是罗列功能，而是比较其客户入口、服务供给、支付模式、运营能力和盈利方式，最后明确富德应该避开哪些“同质化服务包”。                                            |
| **5. 机会挖掘**     | 基于富德的资源禀赋，最值得优先切入的机会是什么？ | 将趋势、客户痛点、未满足需求与竞品空白叠加，筛出机会。例如：以保险客户为入口的全周期健康管理；面向慢病/银发客群的长期管理；团险企业健康福利；保险与养老协同；AI健康助手提高服务效率。机会要满足：**需求明确、富德可获得客户、可整合供给、能形成差异化、可验证商业性。**           |
| **6. 产品方案**     | 用什么产品体系解决问题？             | 建议不是单一App或单项服务，而是“**健康管理平台能力 + 分层会员产品 + 场景化解决方案 + 生态服务网络**”。可形成三级：① 普惠基础服务，服务于存量保险客户；② 高价值健康权益，服务中高端及重点客群；③ 慢病、就医、康复、养老等专项方案。清晰讲明客户旅程、模块关系及富德差异化。 |
| **7. 商业模式**     | 谁付费？怎样持续赚钱？              | 先明确目标客户与付费方：保险公司内部、保险客户、企业客户、合作机构。收入不应只靠C端会员费，可设计“保单附加权益/增值服务、企业健康管理SaaS或服务费、医疗服务转介及供应链收入、联合产品分润”等组合。同步说明成本结构、供给方式、自建与合作边界，以及与保险主业的协同。            |
| **8. 价值分析**     | 值不值得投？对客户、公司和战略分别有什么价值？  | 分三层量化：**客户价值**（健康改善、就医效率、体验与信任）；**商业价值**（续期提升、交叉销售、获客成本下降、理赔及赔付改善、服务收入）；**战略价值**（形成健康数据、服务网络、客户运营及医养协同能力）。最终形成投入产出和关键指标框架。                        |
| **9. 项目计划**     | 如何从概念变成可验证、可复制的业务？       | 按“试点—验证—复制—规模化”推进，而非一次性建设大而全平台。第一阶段选定一个高价值客群和1–2个核心场景，验证使用率、满意度、成本和转化；第二阶段扩充服务网络和产品矩阵；第三阶段与保险、养老、企业服务深度联动。每一阶段都设明确的产品、运营、收入和组织目标。                 |
| **10. 风险及应对**   | 如何确保项目能落地且不失控？           | 覆盖市场风险（客户不使用）、定位风险（与保险主业脱节）、供给风险（服务质量不稳定）、合规风险（医疗资质、数据隐私、营销边界）、资源风险（跨部门协同）、商业化风险（成本高于收益）。每个风险都应有前置机制：试点验证、准入和质控、数据合规、合作伙伴分层、阶段性止损指标等。             |

## 可直接用于开场的一段话

> 健康管理板块的立项，不是为了补充一组健康权益，而是为了回应保险行业从风险赔付向健康经营转型的趋势。  
> 富德拥有客户、保单、支付和养老等资源，但客户在健康咨询、就医、慢病、康复等关键旅程中仍然存在服务割裂和体验不足的问题。  
> 因此，我们将围绕重点客群的高价值健康场景，构建“保险保障+健康管理+医疗养老服务”的协同体系；先通过重点场景试点验证客户价值与经营价值，再逐步形成可复制、可商业化的健康管理业务能力。

## 每一步之间的推导关系

```text
行业与政策趋势
    ↓
富德自身客户和经营问题
    ↓
识别不同客群的真实需求
    ↓
确认市场已有方案与竞争缺口
    ↓
选择富德最有胜率的战略机会
    ↓
设计产品及服务体系
    ↓
建立收入、成本和协同的商业闭环
    ↓
证明客户、商业和战略价值
    ↓
通过分阶段试点落地
    ↓
以风险机制保障规模化发展
```

其中最关键的一句话是：

> **不要从“我们想做什么健康服务”出发，而要从“富德在哪类客户、哪个健康场景中，具备解决问题并形成经营价值的独特优势”出发。**
